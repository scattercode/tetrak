The mkdocs version was hand-transcribed from the generated table and went stale every time the benchmark was re-run -- three times in one day, each needing all 63 cells re-checked by script to catch what the eye missed. Reading the CSV deletes the failure mode: the page cannot disagree with the data because it holds no copy of it. `getCSV` was the obvious function for this and was removed in Hugo 0.123; `transform.Unmarshal` replaces it. The CSV lives at the repository root in evaluation/, outside this site, and is mounted into assets/ by the module mounts in hugo.toml -- os.ReadFile cannot reach above the project root, and copying the file in would reintroduce exactly the second copy this shortcode exists to remove. The markup is a partial rather than a shortcode because the walkthrough layout renders the same table, and a layout cannot call a shortcode. The {{< benchmark >}} shortcode is a thin wrapper over this. Context: a dict of metric - "score" (default) or "sec" boldBest - false to suppress the best-local marking Backends are discovered from the header rather than listed here, so adding one to the harness needs no change on this side. */ -}} {{- $res := resources.Get "evaluation/benchmark.csv" }} {{- if not $res }} {{- errorf "benchmark: evaluation/benchmark.csv is not mounted -- check [module.mounts] in config/_default/hugo.toml" }} {{- end }} {{- $csv := $res.Content | transform.Unmarshal (dict "format" "csv" "delimiter" ",") }} {{- $header := index $csv 0 }} {{- $rows := after 1 $csv }} {{- $metric := .metric | default "score" }} {{- /* "Best" is computed from the _chr columns, so marking it in the seconds view would bold a cell for its accuracy while the cell shows a time -- which every reader would take to mean "fastest".
